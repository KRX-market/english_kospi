# 영문공시 대상 조회 사이트 수정 안내

## 바뀐 동작

- 기준자료 업로드 창을 없애고 GitHub의 CSV 4개를 사용합니다.
- 날짜 기본값은 한국시간 오늘입니다. 선택한 날짜의 누적 대상 공시를 계속 표시합니다.
- '모든 날짜의 누적 결과 보기'를 선택하면 전체 결과를 표시합니다.
- 공시목록을 올린 뒤 '업로드한 목록 반영'을 누르면 기존 목록과 행별로 비교합니다.
- 처음 업로드에서는 모든 공시를 신규로 취급합니다. 이후에는 기존에 없는 행만 추가합니다.
- 같은 분에 추가된 공시나 과거 날짜의 미등록 공시도 추가합니다. 최신 공시 시각은 참고값입니다.
- 새로 추가된 공시를 대상법인·대상서식으로 필터링한 뒤, 링크가 없는 대상 공시만 AI로 검색합니다.
- 이미 찾은 링크는 누적 저장하며 날짜를 바꾸거나 다시 업로드해도 유지합니다.
- 검색 실패 공시는 각 시장의 '미확인 링크 재검색' 버튼으로 다시 검색할 수 있습니다.
- 통신 오류나 서버 오류는 최대 3회 시도합니다. 대기시간은 한 요청당 최대 120초라 전체 작업은 1분보다 오래 걸릴 수 있습니다.
- 링크를 한 건씩 저장해서 중간에 작업이 끊겨도 이전에 저장한 결과는 유지합니다.
- AI 답변의 회사명·전체 제목·날짜·분 단위 시각과 검색 출처 URL을 확인합니다. 'AI 검색 일치'는 원문 대조를 대체하는 인증이 아닙니다.
- KIND 상세 페이지가 검색에 노출되지 않으면 링크를 찾지 못할 수 있습니다. 해당 행은 목록에 남습니다.
- KIND 직접 자동 수집은 하지 않습니다. 사용자가 내려받은 공시목록을 업로드하는 방식입니다.

## 1. 파일 압축 풀기

ZIP을 내려받아 마우스 오른쪽 버튼 → 모두 압축 풀기를 선택합니다.
폴더 안의 파일명에 붙은 다운로드 번호는 GitHub 파일명에 넣지 않습니다.

## 2. GitHub 파일 교체하기

GitHub 저장소를 열고 Add file → Upload files를 선택합니다.
아래 세 파일을 저장소 최상위에 올립니다.

- kospi_engdiscl.py
- requirements.txt
- README.md

이미 같은 이름이 있으면 새 내용으로 교체됩니다. Commit changes를 눌러 저장합니다.
기존 기준 CSV 4개는 변경하지 않아도 됩니다. 이번 압축파일에는 전달받은 기준 CSV 원본을 동일하게 포함했습니다.
기준 CSV의 정확한 이름은 kospi_company.csv, kospi_format.csv, kosdaq_company.csv, kosdaq_format.csv입니다.
최상위 또는 config 폴더에 두면 됩니다. 두 위치에 모두 있다면 최상위 파일을 사용합니다.
실제 저장소 파일명이 다르다면 코드 파일은 현재 Streamlit 실행 파일과 같은 이름으로 교체하세요.

## 3. Streamlit 실행 파일 확인하기

Streamlit 앱 관리 화면에서 실행 파일(Main file path)이 kospi_engdiscl.py인지 확인합니다.
다른 파일명으로 운영 중이라면 그 파일 내용을 수정본 코드로 교체하거나 실행 파일 경로를 변경합니다.
GitHub 변경이 반영되면 앱이 다시 실행됩니다. 반영되지 않으면 앱 관리 화면의 Reboot app을 사용합니다.

## 4. Secrets 설정하기

Streamlit 앱 설정 → Secrets에서 기존 [github]와 [openai] 설정을 유지합니다.
secrets.toml.example은 양식입니다. 실제 키가 들어간 파일을 GitHub에 업로드하지 않습니다.

[github]에는 token, owner, repo, branch, path가 필요합니다.
토큰은 누적 JSON을 보관하는 저장소의 Contents 읽기/쓰기 권한이 필요합니다.
기존 path를 유지해야 기존 누적 결과를 이어서 사용합니다.
기본 누적 파일은 data/disclosure_state.json입니다.

[openai]에는 api_key와 model이 필요합니다.
설정된 모델의 Responses API 웹 검색 지원 및 API 결제 설정이 필요합니다.
이곳의 ChatGPT 이용권과 별도로 앱의 OpenAI API 사용료가 발생할 수 있습니다.
기존 모델 설정을 유지했으며, 실제 키를 사용한 검색 검증은 수행하지 않았습니다.

GitHub 설정이 없거나 읽기에 실패하면 경고를 표시하고 현재 세션에만 보관합니다.
계속 누적 보관하려면 '누적 저장: GitHub 연결' 표시를 확인하세요.
여러 사용자가 동시에 저장한 경우 덮어쓰기를 막고 새로고침을 요청합니다.

## 5. 사이트에서 사용하기

1. KIND에서 공시목록 XLS/XLSX를 내려받습니다.
2. 사이트에서 파일을 올립니다.
3. '업로드한 목록 반영'을 누릅니다.
4. 신규 건수가 표시되고 신규 대상 공시의 링크 검색이 진행됩니다.
5. 조회 날짜를 선택해 코스피·코스닥 누적 결과를 확인합니다.
6. 다음 파일을 올릴 때 같은 절차를 반복합니다. 기존 공시는 중복 추가하거나 재검색하지 않습니다.
7. 링크가 없는 공시만 다시 찾으려면 각 시장의 '미확인 링크 재검색'을 누릅니다.

## HTTP 429가 표시될 때 (추가 수정)

HTTP 429는 API 요청 제한 또는 잔액·결제·사용량 한도 문제일 수 있습니다.
이 수정본은 error.code와 error.type을 확인해 원인을 한국어로 표시합니다.

- insufficient_quota / credit_balance_exhausted: OpenAI API Billing에서 잔액·결제 설정을 확인합니다.
- organization_spend_limit_exceeded / project_spend_limit_exceeded / organization_usage_limit_exceeded: 해당 조직·프로젝트의 지출 또는 사용량 한도를 확인합니다.
- rate_limit_exceeded / rate_limit_error / slow_down: 일시적인 요청 제한입니다. 서버가 보낸 대기시간을 우선 사용하고, 없으면 15초대·30초대로 대기합니다.
- 60초보다 긴 대기를 요구하면 계속 기다리며 요청하는 대신 대기 안내 후 검색을 멈춥니다.
- 원인을 알 수 없는 429는 오류코드를 표시하고 멈춥니다. 결제 문제를 무작정 재시도하지 않습니다.
- 전체 계정 제한이 발견되면 나머지 공시와 다른 시장 검색을 그 실행에서 멈춥니다.
- 새 공시 검색 사이에는 3초 간격을 둡니다. 이는 모든 계정 한도를 보장하는 설정은 아닙니다.

이번 추가 수정은 kospi_engdiscl.py 하나만 GitHub에서 교체하면 됩니다.
requirements.txt와 CSV, Streamlit Secrets는 변경하지 않습니다.
교체 후 사이트의 '코스피 미확인 링크 재검색' 또는 '코스닥 미확인 링크 재검색'을 누릅니다.
기존에 HTTP 429로 저장된 실패 결과도 이 버튼을 누르면 다시 검색합니다.
이미 찾은 링크는 다시 검색하지 않습니다.

API 결제 확인: https://platform.openai.com/settings/organization/billing/overview
API 한도 확인: https://platform.openai.com/settings/organization/limits
여러 조직에 속해 있다면 사이트 Secrets의 API 키가 속한 조직·프로젝트를 확인합니다.
API 키는 공유하지 말고, 개선된 오류 문구만 확인해주세요.

추가 검증: 모의 API 응답으로 잔액 오류 즉시 중단, 일시 제한 후 정상 응답,
Retry-After 준수, 60초 초과 대기 안내, 남은 공시 및 다른 시장의 요청 중단을 확인했습니다.
실제 사용자 계정의 429 원인은 아직 확인하지 못했습니다.

## 종목코드 매칭 수정 (2026-10-07)

이제 대상법인 판별은 이름이 아니라 종목코드로만 수행합니다.
KIND 회사명·CSV 법인명·제출인명의 한글/영문 표기가 달라도 판별 결과에 영향을 주지 않습니다.
기준자료에 종목코드 열이 있으면 그 값을 우선합니다.
기존 CSV는 회사코드만 있으므로 내부에서 대응 종목코드를 만듭니다.
예: HDC 01263 → 012630, IPARK현대산업개발 29487 → 294870.
영문이 들어간 국내 신규 종목코드도 지원합니다.
외국법인 코드 USA11·USA12·HKG21은 별도 확인한 종목코드를 사용합니다.
알 수 없는 회사코드는 임의로 이름 비교하지 않고, 기준자료의 종목코드 열 보완을 요청합니다.

외국법인 종목코드 확인 출처:
- 잉글우드랩 950140: https://kind.krx.co.kr/external/2026/03/25/001057/20260325003471/00636.htm
- 코오롱티슈진 950160: https://kind.krx.co.kr/external/2026/07/27/000756/20260727001769/00634.htm
- GRT 900290: https://kind.krx.co.kr/common/disclsviewer.do?acptno=20260122000354&method=search

사용 방법:
1. 압축 안의 kospi_engdiscl.py 하나를 GitHub의 같은 이름 파일로 교체합니다.
2. Streamlit 앱이 다시 실행되면 조회 날짜를 2026-10-06으로 선택합니다.
3. HDC·IPARK현대산업개발 공시가 표시되는지 확인합니다.
4. 이미 누적 목록에 저장된 공시는 재업로드하지 않아도 새 필터로 표시됩니다.
5. 누적 저장이 되지 않았거나 해당 목록이 없다면 같은 엑셀을 다시 업로드하고 반영합니다.
6. 새로 포함된 과거 공시는 자동 신규 검색 대상이 아닐 수 있습니다. 링크는 '코스피 미확인 링크 재검색'을 누릅니다.

검증: 첨부 오늘의공시(1).xls 207행을 처리했고 해당 투자판단 공시 2건을 확인했습니다.
코스피 대상 결과는 11건 → 13건으로 늘었으며 기존 11건이 유지됨을 확인했습니다.
코스피 252법인·코스닥 148법인의 코드 대응, 이름 변경에 영향 없는 매칭,
대상 외 코드 거절, 외국법인 예외, 영문 포함 종목코드도 테스트했습니다.
회사코드만 든 과거 행은 회사코드를 대응시켜 비교합니다. 종목코드가 잘못 제공된 행을 회사명으로 구제하지 않습니다.
직접 배포와 실제 API 링크 검색은 이번 검증 범위에 포함되지 않습니다.
